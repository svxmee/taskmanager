# TaskManager 

**TaskManager** - веб-приложение для управления задачами с автоматической классификацией по категории и приоритету, а также определением дедлайна на основе введенного текста

Данное приложение представляет собой веб-интерфейс для создания и отслеживания задач. Для классификации можно использовать AI-модель через любой совместимый API поддерживаемого формата или локальный метод, который определяет классификацию на основе ключевых слов

## Возможности

- **Автоматическая классификация:** определение категории и приоритета по введенному тексту
- **Определение дедлайна:** распознование сроков указанных в тексте
- **Выбор классификатора:** прямо в веб-интерфейсе можно переключаться между AI и Keyword классификаторами
- **Управление задачами:** сервис предоставляет возможность создавать, просматривать, удалять или отмечать задачи как выполненные
- **Фильтрация:** можно выбирать необходимые фильтры по категориям и приоритетам, а также сбрасывать их через отдельную кнопку
- **Сортировка:** задачи автоматически сортируются, задачи с ближайшими дедлайнами отображаются выше, а выполненные, наоборот, находятся внизу списка
- **Хранение задач:** задачи сохраняются в SQLite

## Архитектура проекта

Проект разделен на разные компоненты, каждый из них имеет свою роль.

```text
TaskManager/
- Classification/ # классификаторы задач
- Controllers/ # API-контроллеры
- Data/ # работа с базой данных
- Models/ # модели данных
- Services/ # сервисы бизнес-логики
- Migrations/ # миграции Entity Framework Core
- wwwroot/ # веб-интерфейс
- TaskManagerTests/ # тесты
```

Как обрабатываются задачи:

```text
Пользователь
    |
    v
Веб-интерфейс (wwwroot/)
    |
    v
ASP.NET Core Web API (Controllers/TasksController.cs)
    |
    v
Бизнес логика (Services/TaskService.cs)
    |
    v
Выбранный классификатор
    - Classification/AiTaskClassifier.cs
            или
    - Classification/KeywordTaskClassifier.cs
    |
    v
Результат классификации
    |
    v
SQLite (Data/TaskRepository.cs)
```

## Запуск приложения

### Вариант 1. Docker Compose

Рекомендую использовать его, так как он позволяет запустить приложение без необходимости установки .NET SDK.

**Требования:**

- Git
- Docker Desktop

1. Клон репозитория и переход в папку проекта

```bash
git clone https://github.com/svxmee/taskmanager
cd taskmanager
```

2. Настройка переменных окружения

Создайте локальный файл .env на основе шаблона:

```bash
Copy-Item .env.example .env
```

Откройте .env и укажите необходимые значения для AI-классифиатора(подробнее ниже)

3. Сборка и запуск:
```bash
docker compose up --build
```

4. После запуска приложение откроется на:

[http://localhost:8080](http://localhost:8080)

Для остановки контейнеров выполнить:

```bash
docker compose down
```

### Вариант 2. Локальный запуск

**Требования:** 

- Git
- .NET 10 SDK

1. Клон репозитория и переход в папку проекта

## Настройка AI-классификатора

Для классификации задач приложение поддерживает AI-классификатор через OpenAI-совместимый API и локальный классификатор по ключевым словам

Для работы AI-классификатора необходимы:

- базовый URL API-провайдера
- API-ключ
- Название модели, которую вы выбрали у провайдера

Параметры AI-классификатора задаются через переменные окружения. Пример их настройки находится в файле `.env.example` (который мы скопировали при установке в рабочий файл `.env`)

Используемые переменные:

| Переменная | Назначение |
|---|---|
| `AI_API_KEY` | API-ключ для доступа к провайдеру |
| `BASE_URL` | Базовый URL API-провайдера |
| `AI_MODEL` | Название модели |

В текущей конфигурации используется провайдер [RouterAI](https://routerai.ru/). Для смены провайдера необходимо указать его `BASE_URL`, `AI_API_KEY` и доступную модель.

**Классификатор по ключевым словам** не требует API-ключа и использует правила, реализованные в коде

## API

Основные HTTP-операции для работы с задачами:

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/Tasks` | Создание задачи |
| `GET` | `/api/Tasks` | Получение списка задач |
| `GET` | `/api/Tasks/{id}` | Получение отдельной задачи |
| `PUT` | `/api/Tasks/{id}` | Обновление задачи через API |
| `DELETE` | `/api/Tasks/{id}` | Удаление задачи |

Пример создания задачи:

```http
POST /api/Tasks
Content-Type: application/json
```

Тело запроса:

```json
{
    "text": "подготовиться к экзамену завтра",
    "classifierType": "AI"
}
```

## Тестирование

Для проверки приложения создан отдельный проект TaskManagerTests

```text
TaskManagerTests/
- TaskUnitTests.cs
- TaskApiTests.cs
- CustomWebApplicationFactory.cs
```

### Модульные тесты

Модульные тесты содержатся в файле `TaskUnitTests.cs`. С помощью библиотеки Moq зависимости заменяются имитациями, это позволяет делать проверки отдельно от реальных классификаторов и базы данных.

В этих тестах идет проверка следующих сценариев:
- Создание задачи с классификацией
- Создание задачи с дедлайном
- Проверка времени создания (параметр `CreatedAt`)
- Получение задачи по ID
- Обработка запроса на получение несуществующей задачи
- Удаление задачи
- Обработка запроса на удаление несуществующей задачи
- Создание задачи с пустым текстом (ожидаем ошибку ArgumentException)

Дополнительно созданы 5 тестов классификатора:
- `купить препарат` -> Категория: `покупки`
- `сводить сына к врачу` -> Категория: `личное`
- Тесты низкого приоритета: `не срочно купить хлеб`, `неважно, купить хлеб`, `необязательно купить хлеб` -> Приоритет: `низкий`
- Обработка некорректного формата времени `созвон в 10.30` - проверка выбрасывания исключения с указанием `10.30`
- Тест относительной даты: `сделать отчет до пятницы` -> дедлайн отображается на ближайшую пятницу.

### Интеграционные тесты

Интеграционные тесты содержатся в файле `TaskApiTests.cs`. Они проверяют HTTP-эндпоинты приложения. Для данных тестов был создан класс `CustomWebApplicationFactory` наследующий `WebApplicationFactory<Program>` для того, чтобы тесты работали с отдельной тестовой базой SQLite, а не с основной базой приложения

В этих тестах идет проверка следующих сценариев:
- Создание задачи через POST
- Возврат ошибки `400 BadRequest` при создании задачи с пустым текстом
- Получение задачи через GET
- Возврат `404 NotFound` при запросе несуществующей задачи.

### Запуск тестов

Чтобы запустить тесты нужно:
1. Перейти в папку проекта с тестами 
```bash
cd TaskManagerTests
```

2. Запустить тесты командой
```bash

```

Результаты тестов отобразятся в консоли

## Обработка ошибок и ограничения

- При ошибке AI-классификатора приложение показывает уведомление и не создает задачу
- AI-классификатор зависит от доступности внешнего провайдера, корректности API-ключа и от того как ответила модель
- Keyword-классификатор зависит от реализованных правил классификации и ключевых слов
- Дедлайны определяются на основе текста задачи, точность определения зависит от формулировки и используемого классификатора
